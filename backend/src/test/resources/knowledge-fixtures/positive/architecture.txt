Версия документа: 1.0
Дата: 2026-08-16

1. Назначение платформы
=======================
SafeAI Desk используется как управляемый корпоративный AI Gateway. Платформа изолирует арендаторов по organization_id, применяет RBAC и фиксирует действия в аудите.

Основные роли: SUPER_ADMIN для control plane, ADMIN для управления организацией и USER для обычной работы. Frontend guards не считаются границей безопасности: решение всегда подтверждается backend policy.

2. Аутентификация и сессии
==========================
Access token передаётся через HttpOnly cookie. Refresh token также хранится в HttpOnly cookie и ротируется при обновлении сессии. Для небезопасных HTTP-методов используется CSRF-защита.

Access JWT подписывается RS256. Приватный RSA-ключ применяется только для выпуска токенов, а публичный ключ — для проверки подписи. Заголовок kid позволяет выполнять ротацию ключей без мгновенной инвалидизации всех ранее выданных access-токенов.

Email не является частью текущего минимального identity-набора access token. Для авторизации используются стабильные идентификаторы и security epochs.

3. Хранилища данных
===================
PostgreSQL является source of truth для пользователей, организаций, чатов, аудита, usage и metadata Knowledge Base.

Redis используется как coordination layer: rate limits, locks и optional cache. Потеря Redis не должна превращаться в потерю основных бизнес-данных.

S3-compatible object storage хранит байты загруженных knowledge-документов. Локально эту роль выполняет MinIO, а metadata и storage_key сохраняются в PostgreSQL.

4. Knowledge Base
=================
База знаний может иметь видимость ORGANIZATION или MEMBERS. Участники могут иметь уровни VIEWER, EDITOR и OWNER. ADMIN организации имеет административный доступ независимо от membership.

Документ имеет logical identity и версии. Каждая версия хранит original_filename, media_type, size_bytes, sha256 и storage_key. После загрузки создаётся ingestion job со статусом PENDING.

Поддерживаемые входные форматы текущего upload-контракта: PDF, DOCX, TXT и HTML. Файл ограничен 25 MiB по умолчанию.

5. Аудит и эксплуатация
=======================
Audit events должны содержать достаточный контекст для расследования, но не должны сохранять пароли, raw JWT, refresh token, cookies, API keys или полные чувствительные документы.

Production secrets находятся вне Git. Для production они размещаются в /etc/safeai/secrets, а runtime-конфигурация — в environment/config files.

При rollback транзакции после успешной загрузки объекта объектное хранилище должно быть очищено компенсацией, чтобы не накапливать orphan objects.
