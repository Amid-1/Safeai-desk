# SafeAI Desk — этап 3. Единая административная UI-система

Дата: 18.11.2026. База: установленный пакет этапа 2. Статус: код
подготовлен; локальная приемка, visual QA и полный CI не подтверждены.

## Что изменено

- Общий AdminPageHeader и scoped AdminConsole.css для пяти рабочих
  областей: пользователи, организации, аудит, использование, модели.
- Общая типографика, компактные заголовки, таблицы, кнопки создания,
  состояния, бейджи статуса, фокус клавиатуры и reduced motion.
- Компактнее фильтры и строки пользователей и аудита; раскладка
  карточки организации 2 × 2, на узком экране — одна колонка.
- Русские названия ролей в шапке, строках и сведениях. API-значения
  SUPER_ADMIN, ADMIN, USER не изменены.
- UUID и кнопки копирования в сведениях пользователя доступны только
  SUPER_ADMIN, в раскрываемой панели. Ссылка на карточку организации
  доступна SUPER_ADMIN. Отзыв сессий и подтверждения сохранены.
- Ошибка сохранения каталога моделей использует безопасный fallback;
  сообщения локальной валидации сохранены.

## Неизменяемые границы

Backend, RBAC, tenant isolation, optimistic locking, аудит,
Flyway V1–V92, PostgreSQL ACL, CI, lock-файлы, npm audit и Trivy
не изменены. UI не обещает проверенную доступность модели по факту
наличия конфигурации. Нельзя считать неизвестную стоимость нулевой.
Фильтры, счетчики и модельные ограничения используют действующие API.

## Приемка этапа 3

1. Прогнать TypeScript, ESLint, Vitest, production build и полный CI.
2. Проверить при 1920×1080, 1440×900, 1280×720 и 390×844:
   заголовки без наложений, кнопки доступны, горизонтальная
   прокрутка только внутри таблиц, footer и ручной resize работают.
3. Проверить клавиатуру (Tab, Shift+Tab, Escape, восстановление
   фокуса, стрелки на разделителе), открытие и закрытие диалогов,
   недопустимость действий с защищённой организацией.
4. Супер администратор видит идентификаторы только после раскрытия
   технических сведений. ADMIN не должен видеть идентификаторы.
   Проверить сквозные ссылки на организации, модели, аудит, расходы.
5. Сравнить все пять разделов, пустые состояния, ошибки и загрузку.
   Аудит по-прежнему честно экспортирует только текущую страницу.
6. Повторить непройденные проверки этапа 2, включая backend-тесты
   изоляции и фильтрации до пагинации. Скриншоты не заменяют эти тесты.

Следующий этап — № 4: выбор организации, правила моделей,
бюджеты, диагностика и точное представление стоимости.
