# 7.5G.4 — Пользователи и организации

## Граница ответственности

Интерфейс управляет учётными записями, ролями и доступом клиентов. Сервер проверяет
роли, организацию, допустимость изменений и версию записи при каждом запросе.
Скрытие кнопки — удобство интерфейса, не средство авторизации.

| Операция | Backend | Допустимый интерфейс |
| --- | --- | --- |
| Пользователи | GET /api/users/search | Поиск, роли, статус, страницы |
| Итоги | GET /api/users/search/statistics | Общие итоги в выбранной области |
| Карточка | GET /api/users/{id} | Только подтверждённый ответ |
| Изменение | PATCH /api/users/{id} | Разрешённые поля и версия |
| Роль, статус | PATCH /api/users/{id}/roles, /enabled | Подтверждение |
| Пароль | POST /api/users/{id}/reset-password | Проверка и подтверждение |
| Удаление | POST /api/users/{id}/permanent-deletion | SUPER_ADMIN и условия сервера |
| Организации | GET /api/organizations, /search | Список и фильтры |
| Создание | POST /api/organizations | SUPER_ADMIN |
| Карточка | GET /api/organizations/{id} | Проверенный идентификатор |
| Последствия | GET /api/organizations/{id}/disable-impact | До отключения |
| Название | PATCH /api/organizations/{id} | Версия записи |
| Статус | POST /api/organizations/{id}/disable, /enable | Подтверждение |

ADMIN работает с пользователями своей организации; SUPER_ADMIN — в пределах
серверных полномочий, с выбором организации. Системная организация защищена.
Управление SUPER_ADMIN и собственными правами не расширено.

## Состояния интерфейса

- Неудачная загрузка списка: ошибка и повтор, без показа старых результатов.
- Ошибка общих итогов: список остаётся доступен, неизвестные числа показаны как «—».
- Неудачная загрузка карточки: отдельное сообщение; список не скрывается.
- Карточка не подменяется старой строкой списка. Идентификатор ответа должен совпадать.
- Прямая ссылка на пользователя для ADMIN не может раскрыть чужую организацию.
- Запоздалый ответ закрытой карточки не открывает её снова.
- Перед отключением сверяются идентификатор и версия серверного расчёта.
- Во время расчёта нельзя запустить второе действие изменения организации.
- Конфликт версии закрывает устаревшее подтверждение, обновляет результаты
  и требует повторной проверки оператором.
- Ошибка отключения или включения отображается внутри открытого диалога.

## Что не меняется

Правила создания, сброса пароля, удаления, отзыв сессий, ограничения последнего
администратора, защита платформенной организации и tenant isolation остаются
на сервере. Политики RateLimit, Redis, аудит, API, SQL/CONF V1–V101 и workflows
не меняются. В UI не добавляются инструменты ремонта базы или Redis.

## Приёмка

1. Проверить TypeScript, Vitest и действующий coverage baseline.
2. Проверить архитектуру, ESLint, production build.
3. Playwright: прямые ссылки, отказ итогов и доступа к карточке, мобильный экран.
4. На staging с настоящим backend: права ADMIN и SUPER_ADMIN, защищённая
   организация, изменение статуса, отзыв сессий, конфликт двух администраторов.
5. Убедиться, что все девять workflows на PR завершились успешно.

Реальные staging-сценарии и CI обязательны до объявления этапа принятым.
