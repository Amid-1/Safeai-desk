# SafeAI Desk — Super Admin Production UX

Дорожная карта от 18.11.2026. Изменения внедряются отдельными проверяемыми этапами. Статусы обновляются после тестов и установки, а не по факту написания кода.

## Неизменяемые требования

- RBAC, серверная проверка доступа к tenant, защита SafeAI Platform, подтверждения опасных действий, отзыв сессий, optimistic locking и аудит остаются обязательными.
- Не ослаблять CI, npm audit, Trivy, ACL PostgreSQL, Flyway; не редактировать V1–V92. Новые миграции — только при доказанной необходимости, с отдельным ревью ACL.
- Не выдавать данные текущей страницы за глобальные итоги. Не считать отсутствующую цену нулевой. Не подменять реальную проверку доступности состоянием конфигурации.
- Не выводить сырые исключения, SQL, секреты и технические коды в обычных сообщениях. Диагностические идентификаторы — в дополнительной информации по существующим правам.

## Этапы

| Этап | Задачи | Критерий готовности |
|---|---|---|
| 1. Базовая компоновка и организации | Компактное создание организации в модальном окне; серверный общий счётчик; убрать ID/версию из таблицы в сведения; краткий текст без дублей; адаптивная высота списков пользователей и организаций; безопасные сообщения о проверке правил | Создание только по существующему API, ошибки остаются видимыми, системная организация не изменяется, подтверждения сохранены, regression tests и сборка проходят |
| 2. Навигация и каталоги | Серверные фильтры организаций (название, тип, статус), пользователи по организации, отдельная категория супер администраторов, точные счётчики по всем страницам, быстрые переходы из карточки организации к пользователям, моделям, расходам и аудиту; единое меню действий | Права/область видимости проверяются на сервере; фильтры URL и пагинация согласованы; нет фильтрации только загруженной страницы; тесты прямых ссылок, смены организации и ролей |
| 3. UI-система и терминология | Общие заголовки, кнопки, таблицы, пустые состояния, модальные окна; русские названия ролей; безопасные сообщения ошибок, технические сведения по запросу; удобные размеры, клавиатура, фокус и мобильно-адаптивная компоновка | Скриншоты и сценарии на 1440×900, 1280×720, 1920×1080; нет перекрытий и недоступных действий |
| 4. Модели и диагностика | Единый селектор организации, различать настроена/проверена/доступна/разрешена, точное форматирование USD без лишних нулей, RUB только справочно; сохранить и пояснить предупреждения политики, историю версий | Проверка политики привязана к организации и черновику; неизвестные гарантии не считаются подтверждёнными; runtime и каталог не смешиваются |
| 5. Аудит и использование | Единый поисковый выбор организации, компактный журнал, значимые статусы, безопасные подробности; аналитика по организациям, бюджеты и неизвестная стоимость; выбор области выгрузки и серверные лимиты | Неполные данные честно обозначены, аудит/CSV не раскрывает чужие данные или активные формулы; глобальные суммы только из серверных агрегатов |
| 6. Обзор платформы | Отдельный маршрут для супер администратора: реальные счётчики, расходы, состояние AI, события, требующие внимания, быстрые переходы | Нет фиктивных KPI; ошибки и отсутствие данных не представлены нулём; проверена область доступа |
| 7. Готовность к Production | Ревью MFA/повторной аутентификации и жизненного цикла сессий, защита от повышения привилегий и блокирования последнего админа; тесты межорганизационной изоляции, audit immutability, конкурентных операций и секретов; staging, clean/upgrade миграции, CI | Все обязательные проверки зелёные, исключения безопасности явно ограничены и не расширены; результаты staging зафиксированы |

## Статус первого этапа

- [x] Безопасный резервный текст ошибок проверки/сохранения модельных правил без передачи произвольного `Error.message` в UI.

- [ ] Установка на актуальную рабочую копию, визуальная проверка на Mac, полный CI.

## Граница первого этапа

Первый пакет затрагивает frontend и тесты. Серверные фильтры, сквозные переходы, отдельная статистика по типам и ролям и обзор платформы требуют проверки актуального API/backend; не добавлять фиктивные данные или имитацию фильтрации. Технические сведения и опасные операции сохраняются. Статус этапов 2–7: запланированы, не реализованы первым пакетом.
