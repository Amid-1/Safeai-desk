# SafeAI Desk — Super Admin Production UX

Актуализация дорожной карты от 18.11.2026. Этапы устанавливаются последовательно. Реализация в коде не равнозначна прохождению production acceptance.

## Неизменяемые требования

- RBAC, tenant isolation, запрет изменений SafeAI Platform, подтверждение опасных действий, отзыв сессий, optimistic locking и аудит сохраняются.
- Flyway V1–V92, PostgreSQL ACL, CI, npm audit и Trivy не изменяются и не ослабляются.
- Не выдавать значения страницы за глобальные итоги, неизвестную цену за ноль, настроенную модель за проверенную.
- Не выводить сырые исключения, SQL, секреты и диагностические коды в обычном UI.

## Приемка этапа 2

- Каталог организаций: найти организацию по части названия, выбрать тип и статус, проверить фильтр при наличии нескольких страниц; символы `%`, `_`, `!` воспринимаются буквально.
- Пользователи: глобальный счётчик и отдельные роли, выбрать системную/отключённую/обычную организацию; смена фильтра сбрасывает страницу; точные счётчики относятся к выбранной области.
- Открыть карточку организации, последовательно перейти к пользователям, моделям, расходам и аудиту. Вернуться через историю браузера. Из пользователя открыть сведения его организации. Проверить прямые ссылки после обновления.
- ADMIN: вручную послать запросы поиска и статистики с UUID другой организации; сервер должен отказать. UI не должен добавлять чужой scope даже при прямой ссылке.
- Переименование, отключение, включение и сброс пароля используют существующие операции и подтверждения. SafeAI Platform не изменяется.
- Проверить frontend (TypeScript, ESLint, Vitest, production build, Chromium E2E), целевые backend тесты и полный Maven/CI. Зафиксировать результат на фактическом checkout.

Не отмечать этап как production-ready только после установки ZIP. Этап 3 начинать после локальной приемки второго.
