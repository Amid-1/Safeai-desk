# SafeAI-Desk: проверка перехода PostgreSQL с Debian на Ubuntu Noble

Новый основной `infra/postgres/Dockerfile` основан на проверенном `infra/postgres/noble-candidate/Dockerfile`. Сохранены PostgreSQL 16, pgvector 0.8.7, UID=999, права и `/var/lib/postgresql/data`. **Это ещё не доказательство безопасности замены дистрибутива с существующим физическим PGDATA.**

## Обязательный допуск до Production deploy

1. Получить проверенную резервную копию *реальной* production-БД, предпочтительно логический `pg_dump -Fc`/`pg_dumpall --globals-only` и отдельную копию критичных конфигураций. Зафиксировать версии исходной БД, encoding, LC_COLLATE, LC_CTYPE, collation/provider, расширений и контрольные суммы дампа. Не публиковать дамп, пароли и приватные сведения в GitHub.
2. На **отдельном** сервере/изолированной Docker сети создать **новый пустой volume**, и развернуть по digest **именно тот образ**, который был опубликован в GHCR после release с `deploy_to_production=false`. Нельзя монтировать `safeai_postgres_data`.
3. Восстановить роли и данные на изолированной базе, сверить количество объектов/строк, ограничения, внешние ключи, Flyway history/контрольные суммы. Проверить расширение vector, HNSW, сценарии RAG и запросы приложения.
4. На восстановленной копии выполнить: `psql -X -v ON_ERROR_STOP=1 -f infra/postgres/restore-audit.sql`. Проанализировать несовпадения collation (особенно glibc и `datcollversion`). На **тестовой копии** при необходимости выполнить корректные REINDEX и refresh collation по процедуре PostgreSQL, затем повторить проверку. Не выполнять REINDEX/ALTER DATABASE на живой базе без отдельного плана, резервной копии и окна работ.
5. Зафиксировать репетицию восстановления, результат приложения и **точный digest образа**. Только после этого владелец защищённого GitHub Environment `production` может выставить переменную `SAFEAI_NOBLE_RESTORE_APPROVED_IMAGE` равной `ghcr.io/<owner>/safeai-postgres@sha256:<64 hex>`.
6. Production workflow сверяет переменную с digest образа, собранного **в текущем release**. Если digest отличается, деплой заблокирован; требуется повторная проверка или публикация строго воспроизводимого релиза. Значение переменной должно обновляться для каждого нового одобряемого PostgreSQL образа.

Отдельно проверьте, что локали, используемые исходной БД, сгенерированы в Noble. В кандидате включена `en_US.UTF-8`; другие locale требуют анализа до миграции.

## Безопасность текущей интеграции

- CI по-прежнему блокирует все CRITICAL, включая unfixed, и исправимые HIGH/CRITICAL.
- Production по умолчанию запускается с `deploy_to_production=false`. Даже при `true` новый guard отказывает без подтверждённого image digest.
- `infra/docker-compose.yml`, реальная БД, migration scripts и volume не меняются этим патчем.
- GitHub CI показывает совместимость чистой временной базы, но **не** совместимость реальных данных.
- Не переносить сырые дампы на GitHub и не публиковать диагностические результаты с конфиденциальными данными.
