fix(security): synchronize JWT epochs and harden concurrent updates

- добавлен claim organizationAuthVersion в access JWT;
- сохранён стабильный порядок ролей в JWT payload;
- добавлен JsonSecurityErrorWriter в SecurityConfigIntegrationTest;
- исправлена обработка конкурентного создания организаций;
- для проверки дубликатов используется фактический индекс
  ux_organizations_name_normalized;
- только нарушение уникальности имени организации преобразуется
  в ConflictException, остальные ошибки целостности не скрываются;
- одинаковая обработка конфликта применяется при создании
  и переименовании организации;
- исправлена гонка между изменением роли пользователя
  и отключением организации;
- перед получением pessimistic lock отсоединяются устаревшие
  UserEntity и OrganizationEntity из persistence context;
- lazy-связи organization и roles явно инициализируются через
  Hibernate.initialize;
- устранены предупреждения об игнорировании результатов
  Set.size() и OrganizationEntity.getId();
- сохранена независимая инкрементация user token_version
  и organization auth_version;
- исправлена локальная конфигурация срока действия access cookie
  относительно срока действия JWT.

Проверено:
- backend компилируется;
- Flyway успешно проверяет 26 миграций;
- локальная схема PostgreSQL находится на версии 25;
- приложение успешно запускается с профилем local;
- Tomcat запускается на порту 8080.

Примечание:
- предупреждение Netty о native DNS resolver для macOS
  не блокирует запуск приложения.
