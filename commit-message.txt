feat(security): усилить аутентификацию и обработку ошибок

- разделить обработку JWT из Authorization header и access-token cookie
- добавить отдельный AccessCookieAuthenticationFilter для cookie-аутентификации
- сохранить приоритет Bearer-токена из Authorization над access-token cookie
- выполнять cookie-аутентификацию после CSRF-проверки
- требовать CSRF для небезопасных запросов с cookie-аутентификацией
- не требовать CSRF для запросов с Bearer-токеном в Authorization header
- исключить публичные auth-endpoints из обработки access JWT
- преобразовывать ошибки JWT и конвертации claims в стандартный JSON-ответ 401
- унифицировать ответы 401 и 403 через RestAuthenticationEntryPoint,
  RestAccessDeniedHandler, ApiErrorResponseFactory и ApiErrorResponseWriter
- сохранить requestId и единый формат ошибок security pipeline
- актуализировать проверку состояния пользователя и версии токена
  в UserStatusFilter
- вынести PasswordEncoder в общую security-конфигурацию
- использовать DelegatingPasswordEncoder с BCrypt strength 12
  и поддержкой старых BCrypt-хешей без префикса
- удалить дублирующую PasswordSecurityConfig
- обновить интеграционные и модульные тесты для JWT, cookie, CSRF,
  ролей, user status, principal, password encoding и security-ошибок
